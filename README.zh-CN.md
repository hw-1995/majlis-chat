# Majlis

[English](README.md) · **在线演示：** https://hw-1995.github.io/majlis-chat/

一个用 React + TypeScript 写的「帮助中心 AI 助手」，展示一个大模型应用里模型之外的那部分工程：

- 回答**流式输出**，每句话都标注出处（`[1]`），点一下就能看到原文；
- 访客可以填**自己的**大模型 API Key（DeepSeek、OpenAI、通义千问、Kimi、OpenRouter，或任何兼容 OpenAI 格式的接口）；
- 模型可以**调用工具**，用代码算出精确的价格，而不是靠「猜」；
- **混合检索**：关键词检索（BM25）加语义检索（向量），全部在浏览器里运行；
- 中文、英文、阿拉伯语三语界面和知识库，阿拉伯语从右到左排版。

整个项目是静态网站，不需要部署后端，也不保管任何人的 Key。不填 Key 时由内置的模拟服务回答，所有功能照样能演示。

```bash
npm install
npm run dev      # http://localhost:5173
npm test         # 111 个单元测试
npm run build    # 静态站点输出到 dist/
```

## 解决了哪些问题

| 问题 | 做法 |
|---|---|
| 用 POST 接收流式回答 | 基于 `fetch` + `ReadableStream` 手写增量 SSE 解析器 |
| 一个应用接多家模型 | Provider 网关：各家的流式格式统一转换成内部事件格式 |
| 不想替访客付调用费 | BYOK（自带 Key）：Key 只存在 `sessionStorage`，只发给对应厂商 |
| 模型算数不可靠 | 工具调用：有步数上限的 Agent 循环，运行价格计算器、计算器、时钟 |
| 换个说法就搜不到 | 混合检索：BM25 + 浏览器内向量模型，用 RRF 融合排序 |
| 知识库外的问题 | 两路检索都有分数下限；没有资料时，提示词要求模型直接说明「帮助中心没有涉及」 |
| 断线 | 全抖动指数退避重试；模拟服务支持断点续传，真实厂商则干净地重新生成 |
| 上下文无限增长 | Token 预算：保留系统提示词，从最早的对话开始裁剪 |
| 厂商禁止浏览器直连（CORS） | `proxy/` 里一个可选的、不保存 Key 的中转（Cloudflare Worker） |
| 多语言与 RTL | 三语知识库、按语言分词、CSS 逻辑属性 |
| 每个 token 都触发重渲染 | 流式文本放在外部 store 中，只有正在输出的气泡会重渲染 |

## 一个问题是怎么被回答的

```
用户提问
  │
  ├─► BM25 关键词检索 ──────┐
  │                         ├─► RRF 融合 ─► 同一主题只保留一篇 ─► 取前 3 篇作为参考资料
  └─► 向量语义检索（可选）──┘   （分数下限：不相关的问题拿不到资料）
  │
  ▼
系统提示词：「只根据这些资料回答，用 [n] 标注出处，资料里没有就直说」
  │
  ▼
trimToBudget() ── 保留系统提示词，裁掉最早的对话
  │
  ▼
Agent 循环（最多 4 轮）
  │   provider.stream() ──► token ──► 只有 StreamingBubble 重渲染
  │   模型要求调用工具 → 在页面里执行 → 把结果追加进对话 → 再问一次模型
  │   最后一轮不再提供工具，模型必须给出回答
  ▼
带 [n] 引用的回答，以及用到的工具步骤（工具名、参数、返回值）
```

### Provider 网关（`src/gateway/`）

所有模型都通过同一个接口调用：

```ts
interface Provider {
  id: string;
  supportsResume: boolean;
  stream(request, onEvent: (e: StreamEvent) => void): Promise<void>;
}
```

- `openaiCompatible.ts`：适配 OpenAI Chat Completions 格式，DeepSeek、通义千问、Kimi、OpenRouter 等都兼容。它负责拼回分片到达的工具调用参数，并把 HTTP 错误归类为 `auth`、`rate_limit`、`network`、`server` 等错误码。界面据此用对应语言提示原因，而且只对可重试的错误自动重试。
- `mockProvider.ts`：无需 Key 的演示服务。开发时走 HTTP（`server/mockSse.ts`），静态部署时直接在页面内生成回答。

要接入格式不同的厂商（比如 Anthropic Messages API），只需再写一个适配器，网关以上的代码都不用改。

### 自带 Key（BYOK）

演示站自己没有 Key，所以没人能刷站长的额度。访客想用真实模型时，打开「模型设置」粘贴自己的 Key。这个 Key：

- 存在 `sessionStorage`，关闭标签页即清除；
- 只发给所选厂商的地址，不会发给本网站；
- 不会出现在 URL 里，也不会写进日志。

页面启动时不加载任何第三方脚本。唯一的例外是可选的语义检索模型：只有访客打开开关时，才从 CDN 加载。

### 工具调用（`src/agent/`）

模型自己不能运行代码。它只会返回一个结构化请求，例如 `estimate_cost({"plan":"team","seats":5,"months":12,"billing":"yearly"})`。页面执行这个工具，把 JSON 结果发回给模型，模型再据此组织回答。

| 工具 | 作用 |
|---|---|
| `estimate_cost` | 价格和帮助文章用同一张价目表，「600 美元」是算出来的，不是模型预测出来的 |
| `calculate` | 递归下降解析器，只认四则运算。不用 `eval`，因为表达式来自模型，而模型的输入来自用户 |
| `get_current_time` | 模型不知道今天是几号 |

所有工具都是只读的。如果某个工具会改变数据（比如退款），就必须先让用户确认。循环最多 4 轮，最后一轮不提供工具，防止模型陷入死循环、不停消耗额度。工具出错时返回 `{"error": …}` 而不是直接抛异常，这样模型能看到错误并自行纠正。

### 混合检索（`src/lib/bm25.ts`、`src/retrieval/`）

- **BM25** 负责精确词匹配，分词按语言处理：中文按字切成二元组；阿拉伯语去掉变音符号，统一字母变体，并去掉常见前后缀。它有分数下限，所以「怎样才能快速致富」检索不到任何资料，助手会直接说明，而不是瞎编。
- **语义检索**（可选）：用 Transformers.js（WebAssembly）在浏览器里运行 `multilingual-e5-small`，首次需下载约 120 MB。它按意思匹配（问「费用」能找到「套餐与价格」），还能跨语言匹配。
- **RRF（倒数排名融合）**：BM25 分数和余弦相似度不在同一个量纲上，不能直接相加，所以只按名次融合。
- **同一主题只保留一篇**：语义检索可能同时找到同一篇文章的中、英、阿三个版本，只保留读者所用语言的那一篇。
- **兜底**：
  - 库文件先从 jsDelivr 加载，失败则改用 esm.sh；
  - 模型先从 Hugging Face 下载，失败则改用 hf-mirror.com（国内可用）；
  - 都失败时退回 BM25，并在设置面板说明原因。

### 知识库

`src/data/corpus.ts` 是虚构笔记应用 **Qalam Notes** 的 12 篇帮助文章，每篇都有中、英、阿三个版本。产品是故意虚构的：模型无法靠训练数据作答，答对了就说明检索确实起了作用。

## 厂商不允许浏览器直连时

有些厂商不返回 CORS 头，浏览器无法直接调用，页面会提示网络错误。`proxy/worker.ts` 是一个很小的 Cloudflare Worker，可以用来中转：

```bash
cd proxy && npx wrangler deploy
# 然后在页面里：服务商选「自定义」，接口地址填 https://<你的 worker>/deepseek
```

这个中转**不保存任何 Key**，只把访客自己的 `Authorization` 头原样转发。它有四项限制：

- 厂商白名单；
- 只允许 chat completions 路径；
- 只允许指定来源（Origin）；
- 限制请求体大小。

SSE 流原样回传；访客点「停止」时，发往厂商的上游请求也会取消。在真实产品里，限流、公司统一 Key 和审计日志也都放在这一层。

## 目录结构

```
src/gateway/     Provider 接口 · OpenAI 兼容适配器 · 模拟服务 · 设置（BYOK）
src/agent/       runAgent（工具循环）· 工具定义 · 安全计算器
src/retrieval/   向量模型加载 · 向量索引 · RRF 混合检索
src/lib/         SSE 解析 · BM25 · Token 预算 · 引用解析 · 重试退避 · textStore
src/hooks/       useChat（检索 → 预算 → Agent → 引用）· useSemantic（模型加载）
src/components/  对话列表、流式气泡、工具步骤、设置面板、参考资料
src/i18n/        中 / 英 / 阿文案与排版方向
src/data/        三语知识库
server/          `npm run dev` 用的模拟 SSE 接口
proxy/           可选的 CORS 中转（Cloudflare Worker）
```

## 局限

- 知识库只有 36 段短文，所以没有做分块，也没有用向量数据库；这个规模下线性扫描就够了。数据量变大后需要改什么，见 `DEVELOPMENT_GUIDE.md`。
- 断线续传只有模拟服务是无缝的。兼容 OpenAI 格式的厂商无法接着半截回答继续生成，所以会整轮重来。
- 语义检索的分数阈值是按 multilingual-e5-small 设定的起始值，真实产品里应该根据线上问题日志再调。
